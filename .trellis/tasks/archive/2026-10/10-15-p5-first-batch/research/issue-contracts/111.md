# #111 [RM-16] Package the KIRARI Edge Gateway Vercel adapter

## Architecture clarification — 2026-10-15

KIRARI uses the hosting provider's native deployment mechanism. GitHub Actions validates source and produces optional portable artifacts, but does not duplicate the provider's native release controller.

Optional Gateway runtime adapter depends on #102 portable core contract; coordinate export/Preview compatibility with #98 without inheriting P4 approval/admission. Preserve token/cache/platform limitations; no adapter deployment is performed.

---

ROADMAP_ID=RM-16
PROPOSED_PHASE=P5_INDEPENDENT_HARDENING
PRIORITY=P2

GOAL
Package the KIRARI Edge Gateway Vercel runtime adapter for the portable core defined by #102 using Vercel's current Functions model.

SCOPE
Use Node.js Functions for the current recommended Vercel runtime path, with Web `Request`/`Response`/`fetch` at the adapter boundary and Vercel-specific route packaging for `/_kirari/edge/*`. Document environment-scoped secret bindings and map cache levels to documented CDN/HTTP caching and optional `@vercel/functions` Runtime Cache semantics, including environment isolation and limits. Treat older Edge Runtime guidance as a separate compatibility option, not the default architecture.

OUT_OF_SCOPE
- Site export/Preview validation in #98.
- Production/staging deployment, production secrets, or native Site hosting in #99.
- General-purpose proxy paths or claims that Vercel cache semantics match Workers Cache API/KV.

ACCEPTANCE_CRITERIA
- The adapter delegates operation semantics to the portable core and exposes only #102-approved routes.
- Methods, path/query allowlists, fixed upstreams, size limits, and health behavior are tested.
- Vercel route packaging, environment-scoped secret bindings, preview behavior, CDN headers, and optional Runtime Cache behavior are documented and verified in tests.
- Unsupported or unavailable cache capabilities degrade explicitly to CACHE_NONE.
- No deployment is triggered; Site export/Preview validation remains owned by #98.

DEPENDENCIES
#102 capability/core contract. Coordinate any later same-origin Site package integration with #98 without duplicating Site output packaging.

DELIVERY_EVIDENCE
Adapter contract and route map, focused tests, Vercel route/configuration evidence, cache behavior matrix, and no-deploy verification.

PLATFORM_TARGETS
Use Vercel Node.js Functions as the current default.
