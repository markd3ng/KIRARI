# #105 [RM-11] Detect missing canonical files in Trellis adapter synchronization

## Architecture clarification — 2026-10-15

KIRARI uses the hosting provider's native deployment mechanism. GitHub Actions validates source and produces optional portable artifacts, but does not duplicate the provider's native release controller.

Independent application/tooling hardening has no P4, C1, Trusted Sources or release-binding prerequisite. Existing functional requirements and focused tests remain.

GOAL
Make the adapter sync check fail when a canonical Trellis skill has no materialized adapter copy.

SCOPE
Change the existing check to compare canonical and adapter inventories in both directions while preserving intentional exceptions and actionable path diagnostics.

OUT_OF_SCOPE
No broader Trellis format redesign, new adapter framework or manual edits to generated materialized copies.

ACCEPTANCE_CRITERIA
- A missing adapter copy of a canonical file fails the check.
- Stale/extra adapters are classified according to the existing ownership rules.
- Current repository passes and diagnostics identify exact canonical/adapter paths.

DEPENDENCIES
None.

DELIVERY_EVIDENCE
Focused positive/negative fixtures and CI output from scripts/check-trellis-adapter-sync.mjs.
