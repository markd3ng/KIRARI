# #112 [RM-17] Validate and package the KIRARI Edge Gateway EdgeOne Makers adapter

## Architecture clarification — 2026-10-15

KIRARI uses the hosting provider's native deployment mechanism. GitHub Actions validates source and produces optional portable artifacts, but does not duplicate the provider's native release controller.

Optional Gateway runtime adapter depends on #102 portable core contract; coordinate export/Preview compatibility with #98 without inheriting P4 approval/admission. Preserve token/cache/platform limitations; no adapter deployment is performed.

---

PROPOSED_PHASE=P5_INDEPENDENT_HARDENING
PRIORITY=P2

GOAL
Validate and, where documented security and runtime capabilities permit, package a KIRARI Edge Gateway adapter for Tencent EdgeOne Makers.

SCOPE
Use the current Makers Edge Functions handler/context and route packaging, not older classic EdgeOne/SCDN Functions assumptions. Implement only the #102-approved portable-core boundary. Verify Cache API scope/invalidation, Makers KV consistency, environment variables, protected secret handling, runtime limits, and Preview behavior. The current Makers variable API returns values and describes project-wide variables, while the build guide describes Production/Preview scopes; resolve this documentation difference before any GitHub token binding. Preserve explicit PARTIAL/UNVERIFIED findings and use CACHE_NONE when cache behavior is insufficiently documented. Do not enable GitHub token operations unless a supported protected secret binding is verified.

OUT_OF_SCOPE
- Assuming EdgeOne Makers is equivalent to Cloudflare or Vercel.
- Older classic EdgeOne Functions/SCDN runtime implementation.
- Site export/Preview validation in #98, production deployment, or production credentials.
- General-purpose proxy paths.

ACCEPTANCE_CRITERIA
- The adapter exposes only #102-approved routes through Makers Edge Functions and uses Web APIs supported by Makers; unsupported lifecycle APIs are not assumed.
- Cache, KV consistency, environment variables, secret protection, Preview, package/request/CPU limits, and local test limitations are recorded against current Makers official docs.
- Any undocumented cache/secret capability stays disabled or degrades explicitly; token-backed calls remain off until protected secret handling is verified.
- Route/method/query validation, size limits, error handling, and no-secret-leak behavior are tested.
- Packaging and Preview configuration are documented without triggering a deployment.

DEPENDENCIES
#102 capability/core contract. Coordinate any later same-origin Site package integration with #98 without duplicating Site output packaging.

DELIVERY_EVIDENCE
Official-doc capability matrix; adapter contract and route map; focused tests; explicit supported/partial/unverified decisions; no-deploy verification.

PLATFORM_TARGETS
EdgeOne Makers Edge Functions, KV, Cache API, environment variables, route packaging, and Preview only. Current official evidence leaves Cache API semantics, environment scoping, and protected secret-value behavior PARTIAL pending verification: https://pages.edgeone.ai/document/edge-functions ; https://pages.edgeone.ai/document/kv-storage ; https://pages.edgeone.ai/document/environment-variable ; https://pages.edgeone.ai/document/build-guide ; https://pages.edgeone.ai/document/edgeone-cli
