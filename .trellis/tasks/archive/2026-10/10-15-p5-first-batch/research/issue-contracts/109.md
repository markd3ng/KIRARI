# #109 [RM-14] Verify and align Mermaid conversion, gating, and route lifecycle

## Architecture clarification — 2026-10-15

KIRARI uses the hosting provider's native deployment mechanism. GitHub Actions validates source and produces optional portable artifacts, but does not duplicate the provider's native release controller.

Mermaid lifecycle implementation/tests are independent of native Production cutover and custom release approval.

GOAL
Align fenced Mermaid conversion and client-side rendering gates so supported diagrams render on initial load and Astro route changes without claiming behavior that has not been verified.

SCOPE
Trace the rehype conversion from `language-mermaid` fences to `pre.mermaid`, site-level enablement, per-post frontmatter gating, the current frontmatter default, hydration and `transition:after-swap`. Verify the intended disabled/enabled combinations in browser fixtures; correct the conversion/gate contract and navigation lifecycle where evidence shows a mismatch. Check runtime theme changes and rendering failure behavior, documenting any unsupported behavior rather than silently claiming it works.

OUT_OF_SCOPE
No Mermaid dependency upgrade (current origin/main resolves 11.17.2), general diagram redesign, unrelated TOC work, or assertion of a production-visible failure without browser evidence.

ACCEPTANCE_CRITERIA
- The behavior matrix covers global Mermaid disabled/enabled and per-post disabled/enabled, including a fenced diagram.
- A diagram expected to render is converted and initialized; a diagram intentionally disabled has a clear, accessible source/fallback behavior.
- Initial navigation and Astro route swaps render each diagram once without stale or duplicated output.
- Theme changes and renderer errors are browser-checked; supported behavior is implemented and unsupported behavior is documented.
- The site-level and frontmatter policy matches the generated markup and docs.

DEPENDENCIES
Reuse completed RM-04/P3 browser fixtures; no deployment or production settings are required.

DELIVERY_EVIDENCE
Behavior matrix, browser test/network/render evidence for initial load and route swaps, focused regression tests, and documentation of any owner-facing limitation.
