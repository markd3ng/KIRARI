## 2. Redesign C1 for the real Hobby threat model

Implement the smallest safe replacement contract.

The new contract should primarily prove:

1. the credential is authenticated by Vercel;
2. it can operate against the exact approved target:
   - team `team_NsBZHGUVnyygP7veiROKLuUx`
   - project `prj_QNMVdxTkPOad4ynN4fwFCYEST8Jk`
   - project name `kirari-main`;
3. its provider scope is limited to that project where Vercel supports project-scoped PATs;
4. runtime readback does not reveal access to unrelated projects;
5. the credential has a finite lifetime where the provider supports finite expiry;
6. the actual token value is never written to repository files, logs, artifacts, comments, evidence JSON, or tests;
7. revocation or expiry naturally fails closed;
8. Production mutation remains impossible without the separate exact Owner artifact/target authorization;
9. GitHub protected Environment remains the credential boundary.

Prefer a model conceptually equivalent to:

```text
C1_HOBBY_PROJECT_SCOPED_PAT
```

rather than emulating Enterprise RBAC.

## 3. Separate setup-time metadata from runtime proof

Do not require a project-scoped deployment PAT to introspect metadata that Vercel does not permit it to read.

If token label / token ID / expiry / scope metadata requires an Owner/control-plane readback unavailable to the scoped token itself:

- capture that metadata through an authenticated Owner/provider setup read;
- sanitize it;
- never retain the secret value;
- bind it into the concrete manifest;
- bind Owner approval to the canonical manifest digest;
- use runtime provider calls only for properties the Production token can actually prove itself.

Runtime evidence should be fresh and bounded.

A reasonable runtime scope proof may use the provider's project-list/project-read behavior to prove that the credential sees the exact target and no unrelated project, provided current Vercel semantics support that proof.

If Vercel exposes a stronger authoritative token-scope endpoint, use it instead.

Do not use deliberate destructive writes as permission probes.
